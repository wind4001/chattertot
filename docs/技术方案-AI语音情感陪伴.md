# AI 语音情感陪伴（桌面端）技术方案

> 版本 v1.3 ｜ 目标：对标豆包语音聊天，生产级可落地 ｜ 平台：桌面端（Windows / macOS）｜ 模型与算力：火山引擎（豆包）
> 产品定位：情感陪伴 / 虚拟角色（固定人设 + 长期记忆 + 情感共鸣）

**v1.1**：并入首轮评审（会话级路由、回滚漏音、情绪平滑器、记忆校验、AudioWorklet、情感解析容错、P95、埋点/熔断等）。
**v1.2**：并入次轮评审（隐藏假设显式化、边界 case、附录预案、合规与隐私、M3 拆分）。
**v1.3**：火山 API 12 问已对齐——确认 Seed-TTS 2.0 情感机制、A 支持客户端打断/transcript/可调窗口、A 无动态记忆与精细情感、LLM 选型与 SSE 有序、复用 VikingDB；新增决策矩阵与 5 项开工前预验证。

---

## 0. 一句话结论

用户最初的 5 个问题（打断、语音转换、快速响应+判断说完、想象力、情感），火山引擎给出**两条解法**：

- **路线 A（端到端实时语音大模型 API）**：一个 WebSocket 搞定，打断/判断说完/情感/韵律内置，1~2 周可达豆包级体验。但**无动态记忆、无精细情感控制**，仅适合轻量闲聊。
- **路线 B（级联自建：流式 ASR + 豆包 LLM + Seed-TTS 2.0）**：自己编排 EOT/打断/情感 TTS，**完全可控（长期记忆 + 深度人设 + 情感标签）**，是"情感陪伴"产品的终态，但工程量大。

**推荐：路线 A 起步验证产品 → 路线 B 接管做差异化（长期记忆 + 深度人设 + 精细情感）→ 会话级双模式并存（M4+ 上线）。**

## 1. 产品与体验目标（可量化验收）

| 指标 | P50 目标 | P95 目标 | 说明 |
|---|---|---|---|
| 端到端首音频延迟 | < 800ms（目标 <600ms） | < 1200ms | 用户说完 → AI 出声 |
| LLM 首 token（TTFT） | < 500ms | — | "快"的核心指标 |
| 打断响应 | < 200ms | < 350ms | 检测到抢话 → 停 TTS |
| 误打断率（安静环境） | < 5% | — | 咳嗽/呼吸/背景不触发 |
| EOT 体验 | 长句停顿不抢话、短句即时响应 | — | 主观盲测 |
| 情感自然度 | 主观盲测 ≥ 豆包 80% | — | 含情感/韵律/停顿 |
| 长期记忆 | 记住用户事实/偏好/关系 | — | 跨会话延续 |

> **指标适用性**：打断响应指标（<200ms/350ms）**以路线 B 为准**。路线 A 现**支持客户端主动打断**（`conversation.item.truncate`/`cancel`，见 §4.2），可**贴近**该指标，但 A 的音频上行 + 云端链路仍有网络 RTT，无法完全达到 B 的纯本地打断延迟，需**单独测 A 的打断延迟**、单独记录。
> 埋点必须同时采集 P50/P95。以上作为验收基线。

## 2. 核心架构决策：两条技术路线

### 路线 A：端到端实时语音大模型（起步）

端点：`wss://openspeech.bytedance.com/api/v3/realtime/dialogue`

一个 WebSocket，音频进 → 音频出。打断（云端 barge-in + 支持客户端主动打断）、判断说完（`end_smooth_window_ms` + `enable_custom_vad` + `enable_asr_twopass`）、快速响应（端到端流式）、情感（模型自主生成）、人设（`instructions` 系统提示）。

**已确认的能力边界**：
- **记忆**：只能在会话初始化时通过 `instructions` + `conversation.item.create` **一次性注入**用户画像/记忆文本；**无动态向量检索、无增量记忆写入**。默认 20 轮滚动窗口（`HistoryLength` 可调，但调大 → 成本/首包延迟上升）。
- **人设**：`instructions` 支持上千字，限制是请求总 token 而非字数硬上限；超长人设拉高首包延迟与成本。
- **情感**：**无情感参数**，只能靠 prompt 文字引导（"语气温柔克制"），不可量化、不稳定。
- **transcript**：可开启 `conversation.item.input_audio_transcription` 事件拿到完整转写（**可选事件，需确认版本支持**，见 §11.2）。

**结论**：A 适合**轻量闲聊 + 快速验证**；长期记忆、深度人设、精细情感三项**都做不了**，必须落 B。

### 路线 B：级联自建（流式 ASR + 豆包 LLM + Seed-TTS 2.0）

自己编排 EOT / 打断 / 情感。**完全可控**（长期记忆、深度人设、情感标签精细控制）；长期单位成本低；组件可替换。缺点：要自啃 EOT / 打断 / 回滚 / 流式情感，周期长易翻车。

### 决策矩阵（已对齐后）

| 能力 | 路线 A（realtime/dialogue） | 路线 B（ASR+LLM+SeedTTS） |
|---|---|---|
| 长期记忆 | ✅ 一次性预注入；❌ 无动态检索/增量写入 | ✅ 向量检索、动态写入、校验老化 |
| 长人设 | ✅ 上千字；代价 token/首包延迟 | ✅ 可控、可动态裁剪、成本可控 |
| 情感精细控制 | ❌ 仅 prompt 引导，不可量化 | ✅ 情感标签 + 强度 + 句内渐变 |
| 打断 | ✅ 支持客户端下发打断信令；仍有上行 RTT | ✅ 客户端 VAD 低延迟，完全自主 |
| 上下文窗口 | 默认 20 轮，可调（有成本/延迟代价） | LLM 大上下文，记忆走向量检索不塞满 prompt |
| transcript | ✅ 可开事件拿到（依赖版本） | ✅ ASR 天然出文本 |
| 开发量 | 低，黑盒 | 高，大量编排/状态机/回滚 |
| 成本 | 短闲聊更便宜 | 短对话贵；做好缓存深度场景有优化空间 |

### 路由策略（A/B 是两套独立状态，不做句级切换）

- **会话级固定路由**：新建会话时选「快速闲聊（A）」或「深度陪伴（B）」，**全程固定链路**。
- **跨会话迁移（一次性初始化，可选增值功能）**：A→B 时，B 启动时**一次性**导入 A 的转写历史 + 记忆检索。**技术上已确认可行**（transcript 事件），但依赖开启 transcription 事件 + 版本支持；若不支持则砍掉迁移，A/B 完全隔离。
- **双模式并存是终态（M4+）**，M1/M2 只跑一条链路。

## 4. 路线 B 核心链路详细设计

### 4.1 客户端（Electron，桌面专属）

- **音频采集 + AEC**：`getUserMedia({ echoCancellation:true, noiseSuppression:true, autoGainControl:true })` → Chromium AEC3。软 AEC 非万能，外放+高音量+低频仍残留回声。
- **回声策略（分级）**：① 引导耳机；② AEC 兜底；③（后期可选）回声自检动态调阈值。
- **VAD 放 AudioWorklet（音频线程）**：避免主线程卡顿打乱 20ms 帧时序。
- **采样**：上行 16kHz/Int16 PCM；下行 PCM（16/24kHz）。
- **连接**：客户端不直连火山，统一连自家后端 WebSocket。
- **权限/设备变更**：见【附录 A.3】。

### 4.2 打断（barge-in）状态机

```
LISTENING ──用户说完(EOT)──▶ THINKING ──LLM出音──▶ SPEAKING
    ▲                          │（此态不开启打断）        │
    │◀──── 打断：停TTS/取消LLM/清队列 ───────────────────┘
```

- 仅在 **SPEAKING 态**启用 barge-in；有效人声持续 ≥ 阈值（默认 200ms）才触发；渐进式打断（ducking）。
- 触发后：停 TTS、清未播队列、通知后端取消 LLM、切回 LISTENING。
- **路线 A 的打断**：火山同时支持**云端自动 barge-in** 和**客户端主动打断**——客户端本地 VAD 检测人声后，上行发 `conversation.item.truncate`/`cancel` 事件主动终止当前输出。故路线 A 也可做客户端低延迟打断（不依赖云端 VAD），但音频上行 + 云端链路仍有 RTT。

### 4.3 EOT + 预推理 + 回滚（含漏音防护）

- **v1 规则 EOT**：静音时长（500~800ms）+ ASR 增量文本是否以 `。？！` 结尾。
- **v2 多特征 EOT**：静音 + 语法完整度 + 置信度 + 停顿分布 + 上下文 → P(结束本轮)，**需滞回防抖**（附录 A.1）。
- **预推理**：ASR 出 partial 就增量喂 LLM 先跑。
- **漏音防护**：方案① 后端 token buffer（安全阈值 ≥6~8 字 + **buffer 上限 30 字**）；方案② 客户端播放前缓冲（200~300ms，可清空）。
- **回滚无法 100% 消除漏音**，只降概率，不承诺零漏音。

### 4.4 流式 ASR（火山大模型流式语音识别）

- 端点：`/api/v3/sauc/bigmodel`（WebSocket）。输出增量文本 + 时间戳 + 置信度，供 EOT。
- 可配热词表（`boosting_table`）。

### 4.5 LLM（豆包大模型）+ 情感标记解析容错

- **模型**（已对齐）：**主链路 `doubao-seed-2-0-mini`**（低首 token 延迟、高并发、低成本）；**深度/复杂对话降级切 `doubao-seed-2-1-pro`**（情商更强、幻觉更少，但首 token 更慢、更贵）。无专门"纯文本流式语音 LLM"，realtime/dialogue 是独立端到端模型。
- **流式有序性**：方舟 OpenAI 兼容 SSE 协议保证事件有序（TCP 字节流有序），**不会乱序，无需序号重排**；但网络中断/重连会丢失未推送 chunk，需做**断线重连续接**逻辑。
- **输出协议**：LLM 输出文本 + 情感标签（`{"emotion":"惊喜","intensity":0.8,"text":"..."}` 或内联 `[惊喜|0.8]`）。
- **解析容错**：解析失败 → 丢弃标签、纯文本、TTS 中性兜底。禁止 markdown/换行/代码块。
- **故障隔离**：情感标签是附加信息，M3 先不带情感跑通，M4 再接。
- **长度控制**：强制短句分段。

### 4.6 情感链路（双向，机制已确认）

- **用户情绪（SER，触发式）**：v1 用 LLM 从文本+上下文推断（含情绪关键词 + 问句/感叹句才调用），标签用少量离散值（neutral/sad/happy）。v2 上音频级 SER。
- **AI 情绪（Seed-TTS 2.0 已确认机制）**：
  - 支持显式情感标签 `emotion`（happy/sad/neutral 等）+ **`emotion_scale`（强度 1~5，非线性）**；
  - **句内渐变**：通过**文本内嵌标签**（如 `[开心]...`)实现——LLM 流式输出的文本里嵌入标签，TTS 读到标签后切换情感。**不是独立 API 参数**，TTS 任务启动后顶层参数不可中途改，只能靠文本内嵌标签。
  - **边界**：① Seed-ICL 2.0 **复刻音色需开"参数透传模式"才能识别情感标签**；② 标签切换有小段音频缓冲延迟，非毫秒级无缝。
- **情绪平滑器**：最大变化步长（±0.2）+ 指数滑动平均 + 向中性自然回落 + **intensity 下限**（低于阈值归 neutral）。
- **音色复刻（Seed-ICL 2.0）**：5 秒参考音频复刻音色；**仅限本人声音**；生成音色 ID 后**原始参考音频即删**。
- **句内渐变降级预案**：见【附录 A.4】（标签效果不稳 → 单轮固定情感）。

### 4.7 人设引擎 + 记忆系统（情感陪伴核心）

- **人设引擎**：system prompt 模板 + 生成参数；多角色各一套 + 专属音色。深度人设放 B（可动态裁剪 prompt）。
- **记忆分层**：短期（当前会话 + 情感状态）；长期（画像 + 事实 + 情感记忆）。
- **记忆底座（已对齐）**：**复用火山 VikingDB 向量库**做存储/检索，省去自建向量库；但**记忆抽取、过滤、校验、去重、老化、管理 UI 仍需自研**，火山无开箱即用的完整记忆引擎。
- **记忆校验（防污染/幻觉）**：`validated=false` 默认不进检索池；相似度比对去重；（可选）抽样问用户确认。
- **检索相关性校验指令**：召回记忆后 prompt 加"无关记忆忽略，不要强行引用"。
- **老化策略**：`last_accessed_at` → 降 importance → 归档（不删可恢复）。
- **检索预算**：注入记忆 token 可配置上限（初始 800）。
- **记忆抽取治理**：队列优先级（活跃用户优先）+ 单用户并发 1。
- **记忆管理 UI（M4 必做）**：用户可查看/删除单条记忆。

## 4.8 会话生命周期

- 用户离场/idle（可配 5 分钟）→ 挂起/结束 + 触发记忆抽取。
- 会话结束 → 记忆抽取。
- 断线重连：A 用 `dialog_id` 续接、B 从 Redis 恢复上下文。
- App 失焦/系统空闲 → 暂停麦克风采集。

## 7. 后端架构、安全与可观测性

- **密钥只在服务端**；**鉴权**：账号 → token → WS 握手鉴权；**无状态编排器**（Redis + 横向扩容）。
- **流式转发**：客户端↔后端 WS，后端↔火山 SDK。
- **熔断/限流（按错误码区分）**：400 不重试（程序 bug 重试只扣钱）；5xx 有限重试（≤2 次指数退避）；429 熔断冷却。连续失败 N 次 → 降级，不疯狂重试。
- **埋点事件**：`vad_trigger`、`barge_in_trigger`、`barge_in_false_positive`、`eot_trigger`、`eot_false_positive`、`eot_false_negative`、`rollback_trigger`、`tts_first_audio`、`llm_rollback_token_count`、`memory_retrieval_token_count`。
- **异步任务**：记忆抽取、画像更新、埋点走队列，不阻塞实时链路。

### 7.5 合规与数据隐私（情感陪伴红线）

- **内容审核**：路线 A 开 `strict_audit`；路线 B LLM 文本输出接内容审核，定义内容边界（拒绝诱导/色情擦边/自伤违法）。
- **心理/医疗硬边界（system prompt 必写）**："你不是心理医生，不能做诊断、不能替代专业咨询师；遇严重抑郁/自伤表述给引导建议、提示寻求专业帮助，禁止诊断。"
- **未成年人保护**：注册/首启提示，必要时年龄门槛。
- **数据隐私**：对话文本/语音存储时长、加密写入隐私协议；提供用户删除权/导出权；参考音频生成音色 ID 后即删。

## 8. 成本估算（模型 + 已对齐定性结论）

豆包大模型 2.1 Pro（260915）公开价：推理输入 6 元 / 输出 30 元 / 缓存命中 1.2 元（每百万 token）。

- **定性结论（已对齐）**：短闲聊 **A 通常更便宜**（打包计费、链路优化）；深度陪伴（大量记忆注入 + 长 prompt）**B 做好 prompt caching 后可追平甚至低于 A**（B 可精细裁剪记忆、缓存前缀）。**双链路并存 = 两套工程/测试/埋点/告警，维护成本翻倍**，需评估研发人力。
- **降本要点**：prompt caching 缓存固定前缀；闲聊走 A 或 mini；长上下文用检索注入非全量塞历史；EOT 滞回 + buffer 上限降低回滚浪费；埋点审计 `llm_rollback_token_count`。

## 11. 对齐结果与剩余预验证项

### 11.1 已确认结论（12 问对齐后）

1. **长期记忆**：A 仅会话级一次性注入（`instructions`），无动态检索/增量写入 → **真实长期记忆必须 B**；可复用 VikingDB 向量底座，记忆逻辑（抽取/校验/去重/老化/UI）自研。
2. **情感**：Seed-TTS 2.0 支持 `emotion` + `emotion_scale` + 文本内嵌标签句内渐变；A 无情感参数（仅 prompt 引导）→ **精细情感必须 B**。
3. **打断**：A 支持客户端主动打断（`truncate`/`cancel`），可贴近 B，但仍有上行 RTT。
4. **transcript**：可开 `input_audio_transcription` 事件拿转写 → A→B 迁移可行（依赖版本开启）。
5. **上下文**：20 轮为默认窗口，`HistoryLength` 可调，调大有成本/延迟代价。
6. **LLM**：B 默认 `doubao-seed-2-0-mini`、深对话切 `2-1-pro`；SSE 有序无需重排，需断线重连续接。
7. **成本**：短闲聊 A 便宜、深度 B 做好缓存可追平、双链路维护翻倍。

### 11.2 开工前预验证项（需火山技术支持核实）

1. realtime/dialogue 当前开放模型版本：`conversation.item.input_audio_transcription` 转写事件是否可用；
2. realtime/dialogue `HistoryLength` 最大可调上限 + 调大后首 token 延迟实测（P50/P95）；
3. Seed-ICL 2.0 参数透传模式下内嵌情感标签的稳定性 + 标签切换的音频缓冲延迟；
4. 成本：按典型对话分布（平均每轮 token、时长）拿火山精确报价；
5. VikingDB 向量库：并发、检索延迟、存储单价，评估能否直接做记忆底座。

## 附录 A：技术预案 / 降级方案（不改主链路，按需启用）

### A.1 EOT 滞回防抖（M6 EOT v2）
P(EOT) 在阈值附近振荡会反复启停 LLM 烧 token。需滞回：上升（>0.6 维持 250ms）触发 EOT；下降（<0.3）取消 EOT 触发回滚。上升/下降阈值不同 + 维持时间。v1 规则版用简单时间防抖。

### A.2 记忆检索 score 公式（可配置）
```
score = sim * 0.6 + importance * 0.3 + recency_decay * 0.1
recency_decay = exp(-k * days_since_last_access)   # k 可配置
```
权重与 k 放配置中心。

### A.3 麦克风权限丢失 / 音频设备切换
- `devicechange` + 权限状态监听；麦克风丢失 → 切 LISTENING、停上行、友好提示、重置状态机。
- 设备切换 → 重建音频链路、重置 Silero VAD、清播放缓冲。
- 扬声器静音（音量 0）→ 无回声，可自动调低打断阈值。

### A.4 Seed-TTS 句内情感渐变降级预案
句内渐变依赖 LLM 流式文本里动态插标签。若标签效果不稳 → **单轮回复固定同一情感标签**，放弃句内渐变，仅轮间平滑过渡。
