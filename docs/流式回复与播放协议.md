# 小云流式回复与播放协议

角色展示、系统提示词和记忆摘要统一使用「小云」。
历史录音文件名中的 xiaoyue 和 ASR 同音字容错保留原样。

## 回复流程

后端流式读取 LLM 正文，按句号、问号、叹号、分号和换行切句。
无标点长句限制到 100 字；句子队列最多缓存两句，TTS 依次合成。
取消一轮会关闭对应的 LLM 和 TTS 流，不继续发送旧轮次音频。
HTTP `/transcribe` 仍使用完整回复，方便录音接口调试。

## WebSocket 事件

| 方向 | 事件 | 含义 |
|---|---|---|
| 后端 → 前端 | `turn_start` | 新回复开始，清除旧播放队列 |
| 后端 → 前端 | `ai_text_delta` | 本轮新增文字，追加到同一条消息 |
| 后端 → 前端 | `ai_audio` | 本轮 24kHz、16bit PCM 音频块 |
| 后端 → 前端 | `ai_text` | 本轮最终完整文字，用于覆盖流式显示 |
| 后端 → 前端 | `audio_end` | 本轮不会再有音频，客户端可检查是否播空 |
| 前端 → 后端 | `play_end` | 本轮音频已发完且客户端实际播放队列已清空 |
| 后端 → 前端 | `response_error` | 本轮失败提示，附 `stage` 和用户可读 `message` |

以上回复事件都带整数 `turn_id`；连接内单调递增，允许跳号。
前端忽略旧轮次的文字、音频和结束事件。
后端只接受当前轮次、已发完音频的 `play_end`，忽略提前、重复和缺编号的确认。
`user_speaking` 是连接控制事件：立即停止当前播放，等待新的 `turn_start`。

音频暂时播空不会触发确认，必须先收到 `audio_end`。
播放超时兜底按每个音频块的发送时间累加剩余播放时长，并留两秒余量。
这次协议需前后端同时更新；页面长时间开着时，升级后需要刷新。

## 耗时日志

后端输出 `[TIMING]` JSON，包含 `trace_id`、`turn_id`、`stage`、`elapsed_ms`。
阶段包括判停、KWS、声纹、ASR、记忆读取、LLM 首段正文、TTS 开始、
首段音频、音频发送完、播放确认、取消和超时。
固定唤醒回应使用 `fixed_first_text` / `fixed_done`，不混入 LLM 阶段统计。

时间起点是本句最后语音之后的静音起点估计值，因此包含判停等待。
`first_audio` 是服务端首段 PCM 就绪时间，不等于扬声器实际发声时间。
日志不包含新的音频内容或密钥字段。

## 错误与记忆

LLM 首段音频前失败时，显示错误并尝试一次简短语音兜底。
已经输出音频后发生错误时，显示错误，播完已发送部分，不重播整段。
TTS 返回空音频或抛错会显示明确提示。
TTS 流读取超时为 15 秒，单句合成总时限为 30 秒。
只有成功生成并合成的完整回复写入对话历史；生成或合成中被取消的不写入。
已合成完毕的回复先存档，再等待客户端播放确认。
