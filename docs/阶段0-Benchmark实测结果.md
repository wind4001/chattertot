## 一、已完成实测

### C 项：声纹 CAM++ 提取延迟 ✅ 达标

| 音频时长 | 提取耗时 |
|---|---|
| 2.6s | 45ms |
| 4.2s | 72ms |
| 40s（超长） | 667ms |

**结论**：对话一个 turn（2~5s）的声纹提取只要 45~72ms，百毫秒级达标。
**决策**：v1 沿用现有 CAM++，不换 3D-Speaker（省迁移成本）。

### 补充实测：声纹可靠性的音频时长要求

| 片段时长 | 与完整音频的声纹相似度 |
|---|---|
| 150ms | 0.013（随机） |
| 300ms | -0.027（随机） |
| 500ms | 0.444 |
| 1000ms | 0.591 |
| 2000ms | 0.943 |

**结论**：声纹 embedding 需要 **1~2 秒音频才可靠**，150ms 短音频完全无效（同源都仅 0.013）。
**影响**：barge-in 打断不能做声纹校验（打断音频太短）——打断改为「人声 ≥150ms 停 TTS」，声纹过滤留给整段判停后。

### A 项：sherpa-onnx Zipformer 流式 ASR

**延迟 ✅ 达标**（官方音频，能识别的场景）：

| 指标 | 数值 | 目标 |
|---|---|---|
| 首 token | **56ms** | <500ms |
| 整段(8.8s) | 427ms | <800ms |
| RTF | 0.048 | — |

**精度 ❌ 不达标**（真实对话音频，儿童语音）：

| 音频 | SenseVoice(原始) | Zipformer(AGC归一化后) |
|---|---|---|
| 918.wav | 讲个故事吧 ✅ | 行那我们再来做什么事一天 |

**附加发现**：Zipformer 对低音量敏感——原始音量直接识别空，需 x8 增益才开始吐字；但即便 AGC 归一化后识别内容仍胡言乱语。

## 二、重大结论（推翻 v1 基线）

**sherpa-onnx Zipformer streaming 不适合做 v1 主 ASR。**

- 它的流式延迟极好（首 token 56ms），但**对我们真实场景（儿童语音 + 家庭环境 + 低音量）的识别精度远不如 SenseVoice**。
- SenseVoice 原始音量即正确识别；Zipformer AGC 后仍胡言乱语。
- 根因：bilingual-zh-en 是 2023-02 老模型 + streaming 模式本身精度低于离线 + 儿童语音鲁棒性差，三重叠加。

**由此暴露的核心矛盾**：

> EOT 状态机 + tentative 预生成**强依赖流式 ASR 的 partial 文本**；
> 但**能跑的流式 ASR（Zipformer）精度差到 partial 文本不可用**，
> 而**精度好的 SenseVoice 是非流式、无 partial**。

调研文档的最大亮点（流式 partial 驱动自适应 EOT + tentative）在「纯 CPU + 儿童场景」下，**因为流式精度不足而失效**。

## 三、待决策（需用户 + 豆包共同拍板）

### 方向 1：务实降级（推荐先做）
**TEN VAD + 声纹前置 + 自适应静音判停 + SenseVoice 整段识别**
- EOT 判停靠「VAD 人声检测 + p50/p90 自适应静音窗口」，**不靠 partial 语义**（绕开流式精度差）
- 识别靠 SenseVoice（精度好）
- 代价：失去 tentative 预生成、失去语义判停（标点/虚词）

### 方向 2：继续找更强的流式 ASR
- Qwen3-ASR streaming：宣称儿童鲁棒性好，但 CPU 延迟未知（transformer 0.6B 大概率 >800ms），且流式 ONNX 可能无现成版
- Paraformer-large streaming：精度更好，CPU 延迟也更高
- 需先实测延迟 + 精度，成本高、结果不确定

### 方向 3：混合双模型
- 流式 Zipformer 仅做端点/人声检测（不识字），SenseVoice 做最终识别
- 本质等于方向 1，Zipformer 退化为 VAD，不如直接用 TEN VAD
