## 一、要解决的问题

「只认孩子、不回家长」在 v1 纯声纹（CAM++ 0.35）下只能做到**过滤陌生人**，家长 vs 孩子区分不开（家人声纹相似度 0.57~0.89 区间重叠）。唤醒词从另一个角度切入，解决其中两个最头疼的问题：

1. **声纹注册污染**：之前注册用 18s 混合音频（孩子+家长），参考声纹被污染。唤醒词「小月小月」是短促、单说话人的干净样本，注册/验证用它，天然干净。
2. **会话起点控制**：家长不喊唤醒词就不激活，从源头消灭"家长主动说话被误回"。

## 二、不解决的问题（诚实声明）

- **会话期间家长插话**：唤醒后进入连续对话，家长插话仍靠声纹过滤（区分不开）。唤醒词管「启动」，不管「持续过滤」——后者仍需 v2 的 TSE（目标说话人提取）+ N 卡。

## 三、技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 唤醒词引擎 | **openWakeWord** | Apache 2.0、CPU 实时、模型几 MB、支持自定义训练 |
| 唤醒词 | 「小月小月」 | 与小月人设呼应，双字叠词易发音、儿童友好 |
| 部署位置 | 后端（WebSocket 音频流入口） | 浏览器前端资源有限，后端处理更稳 |

> 备选：Porcupine（Picovoice）也支持中文唤醒词，但有免费额度/许可限制，仅作 fallback。

## 四、集成方案

```
麦克风音频流（16kHz PCM）
→ 唤醒词检测（openWakeWord，待机态持续监听「小月小月」）
    ├─ 未命中 → 丢弃（待机，不跑 VAD/声纹/ASR，省 CPU）
    └─ 命中 → 进入活跃会话
        → 对唤醒词音频段提取声纹
            ├─ 首次：注册参考声纹（干净样本）
            └─ 之后：验证（相似度 < 阈值 → 非孩子，忽略）
        → 进入连续对话（VAD + 声纹 + 固定 800ms EOT + SenseVoice + LLM + TTS）
        → 会话静默超时 → 回到待机
```

## 五、落地步骤

1. 装 openWakeWord + 收集「小月小月」正负样本（孩子多次录音 + 家长/噪声负样本）
2. 训练自定义唤醒词模型
3. 后端音频流改造：先过唤醒词检测，命中才进 VAD/声纹
4. 声纹注册流程改为「唤醒词音频注册」（替代当前任意一句话注册）
5. 会话静默超时回待机

## 六、成本与定位

- 成本：约 1~2 天（主要耗时在样本收集 + 训练 + 后端音频流改造）
- 定位：**v1.1 独立迭代**，不阻塞 v1 基线；v1 先真机验证识别/判停体验
- 与 v1 的关系：唤醒词是「声纹的前置门」，不是替代；唤醒后仍用 CAM++ 0.35 过滤陌生人
