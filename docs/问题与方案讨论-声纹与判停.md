# 语音陪伴项目：两个待解决问题 + 方案讨论

> 求豆包一起讨论：下面的「搜到的方案」和「我的倾向」都不确定是否最优，想听听你的判断和建议。

---

## 项目背景（一句话）

桌面端 AI 语音情感陪伴（给小朋友用）。当前架构：**本地 SenseVoice ASR（Docker）+ DeepSeek V4 Flash（LLM）+ 豆包语音合成（TTS）**，连续对话（VAD 判停）已跑通。现在遇到两个体验问题。

---

## 问题 1：声纹 / 说话人区分（多人场景）

### 场景

小朋友和 AI 聊天时，**家长在旁边说话**，AI 会把家长的话也识别、回复（既不该打断、也不该回家长）。

### 当前做法

CAM++ 声纹提取 + 余弦相似度阈值（0.6）。第一段语音自动注册为参考声纹，之后每段语音提取声纹、对比参考声纹，相似度 <0.6 就忽略。

### 遇到的问题（有实测数据）

- 注册的第一段音频太长（**18 秒**），把**孩子+家长的声音混在一起**注册了，参考声纹变成"混合声纹"，之后所有人的声音都跟它相似（都 ≥0.6），全放行。
- 实测两两相似度矩阵（同一家庭的几段语音）：

```
       段1   段2   段3   段4   段5
段1   1.00  0.68  0.82  0.78  0.85
段2   0.68  1.00  0.67  0.57  0.66
段3   0.82  0.67  1.00  0.82  0.89
...
```

  可以看到**一家人（孩子+家长）的声纹相似度天然就高（0.57~0.89）**，0.6 的阈值根本区分不开。

### 搜到的成熟方案

1. **目标说话人 ASR（Target Speaker ASR）**：把目标人（孩子）的参考声音当"钥匙"，模型**直接从混合语音里只转录目标人**，其他人自动输出空文本（拒识）。成熟案例：**小米开源 Xiaomi-CocktailASR-1**、NTT 的 SpeakerBeam。
2. **声纹验证**（CAM++/ERes2Net）：我们当前做法，简单，但"一家人声纹相似、短音频不准"。
3. **波束形成 / 定向拾音**：麦克风阵列空间定位，需要麦克风阵列硬件，桌面不适用。
4. **唤醒词锁定**：唤醒词 + 声纹锁定目标人，需要唤醒词，偏音箱场景。

### 我的倾向

**目标说话人 ASR（CocktailASR）才是正解**——它是专门为"从混合语音中只抽目标人"训练的，而 CAM++ 是通用说话人嵌入，对"一家人声纹相似"区分度不够。

### 想和豆包讨论的点

- CocktailASR 适不适合桌面单麦克风、家庭场景？部署门槛高不高？中文效果如何？
- 和 CAM++ 声纹验证比，哪个更实际？
- 有没有更好的、我没搜到的方案？

## 问题 2：连续对话的开始 / 结束判断不灵敏

### 场景

判停（判断"用户说完了没"）不灵敏——判停窗口短了会**切断说话慢/爱停顿的人**（尤其小朋友），长了又导致**响应慢**。

### 当前做法

能量 VAD（RMS 阈值）+ 静音判停窗口（**2.5 秒**，因为纯能量 VAD 分不清"停顿"和"说完"，被迫拉长窗口来避免误判）。

### 遇到的问题

- 搜到的一句关键结论，直指根因：**"纯静音阈值判停必然失败——它分不清'停顿思考'和'说完'，也分不清'人声'和'咳嗽、叹气、噪声'。"**
- 实测：说话中间停顿会被切断（只识别半截），或者判停太慢。

### 搜到的成熟方案

成熟架构是**两层**：

```
能量门控 → VAD（是不是人声）→ 语义判停（说没说完）
```

**VAD 层**（替代我们的能量 VAD）：
- **Silero VAD**（MIT 开源，1M 参数，<1ms）
- **TEN VAD**（声网开源，更优）

**语义判停层**（关键，我们完全没有）：
- **TurnSense**（百融开源，**47M 参数纯 CPU**，三分类：`Complete` 立即响应 / `Incomplete` 继续等 / `Invalid` 咳嗽叹气噪声忽略）
- **LiveKit turn-detector**、**Pipecat Smart Turn**、**TEN Turn Detection**（声网）

**配套工程参数**（成熟项目默认值）：
- 最短语音 250ms（过滤咳嗽）
- 静音 hangover 500~800ms（判停等待）
- Pre-roll 300~500ms（防首字截断）
- **Flush trick**：判停后给流式 STT 发 flush 强制立即出结果，压缩延迟

### 我的倾向

**Silero VAD + TurnSense 语义判停**，彻底解决"分不清停顿和说完"。

- 这几个语义判停模型，能不能和我们的"目标说话人 ASR"合并（即一个模型同时解决"只认孩子 + 判停"）？
- 有没有更好的组合方案？
