# 便宜级联方案 · 实施计划（Docker 版）

> 目标：给自己家小孩用的语音情感陪伴，**简单部署（Docker）+ 控制成本（本地 ASR + 便宜 LLM/TTS）**
> 这是路线 B（级联）的落地版，替代之前路线 A（端到端 realtime，80元/百万太贵）。

**v1.1 变更**：并入评审——SenseVoice 非流式降延迟方案、回声防误打断、EOT 滞回可配置、预推理锁、LLM 情感标记格式与容错、WS 序号/水位控制、记忆异步抽取+儿童内容过滤、配额优雅降级、Docker 资源限制、P1 场景测试、P7 单独分支。

## 2. 三组件选型（已确认）

| 组件 | 模型 | 价格 | 接口 | 部署 |
|---|---|---|---|---|
| ASR | SenseVoice-Small（本地） | 免费 | HTTP（自封装） | Docker + FunASR 镜像 |
| LLM | `deepseek-v4-flash` | 1 元/百万输入、2 元/百万输出 | OpenAI 兼容 SSE | 云 API |

## 4. 接口设计

| 链路 | 协议 | 说明 |
|---|---|---|
| client ↔ backend | WebSocket | 上行 JSON + PCM（**带序号**）；下行 JSON 事件 + PCM |
| backend ↔ asr | HTTP POST | 上传一段 PCM → `{text, emotion}`（emotion 是整段统计标签，粗粒度） |
| backend ↔ LLM | SSE | OpenAI 兼容，流式文本 + 情感标记 |
| backend ↔ TTS | HTTP Chunked | 文本 + 语音指令(情感，映射成 context_texts) → 流式音频 |

## 5. 状态机（核心工作量）

级联没有内置打断/判停，这块是真正的代码。分两阶段：

**M2（先跑通）**：
- VAD 分片 → 静音判停（EOT 阈值**可配置**，默认 600ms，滞回 400~800ms）→ 整段送 ASR → 文本送 LLM → 回复送 TTS
- **长句保护**：音频 >1.8s 无静音，强制切分片提交 ASR（防超长句卡死）
- 三态：LISTENING → THINKING → SPEAKING
- 不做打断、不做预推理

**M3（再上硬骨头）**：
- **打断（barge-in）+ 回声抑制（最大坑）**：
  - 浏览器 `echoCancellation: true` 兜底
  - SPEAKING 态提高 VAD 阈值（播放窗口内人声置信度衰减）
  - 最小人声持续 150ms 才判打断（过滤瞬间爆音）
- **预推理 + 回滚 + 预推理锁**：partial 文本 <4 字不启动 LLM；连续多次回滚时临时关预推理，降级 M2 模式（防反复刷 API 推高成本）
- EOT 升级：静音 + 语义 + 滞回防抖

## 6. 实施细节（评审补充，落到代码）

**SenseVoice 降延迟**（非流式的应对）：
- P1-P5 用「超时强制分片 1.8s」；P5 稳定后可选「滑动窗口 400ms + 200ms 重叠 + 文本去重合并」
- CPU 不够可换 int8 量化版；背景噪音大时加 noisereduce 预处理
- 注意：SenseVoice 的情绪标签是**整段统计值，非逐字实时**，只当粗粒度参考

**LLM 情感标记**：
- 固定标记语法（如 `【emotion:happy,speed:1.1】`），不混在自然语言里
- 后端解析后**映射成 Seed-TTS 的 `context_texts`/情绪语法**（不是直接透传）
- 解析失败 → 自动降级中性音色，**不能卡住 TTS**
- 数值钳制在 Seed-TTS 支持范围内；情绪平滑器加插值（最少保持 300ms，防忽上忽下）

**WS 音频传输**：
- 每个 PCM 包带序号，后端排序，丢弃迟到 >120ms 的包
- 水位控制：缓冲堆积时丢老数据，防长时间会话内存涨

**记忆（儿童对话跳跃强）**：
- 短期会话记忆：固定窗口截断（防上下文越滚越长，token 暴涨）
- 长期记忆：异步抽取（不阻塞主链路），触发式检索（话题切换或每 N 轮一次，不每轮查）
- **儿童内容过滤**：SSE 收到文字后、送 TTS 前，本地词表拦截

**配额熔断（双层）**：
- 字符配额（LLM + TTS 累计字符）+ 时间软限制
- 熔断后**优雅降级**：切提示语音"今天聊够久啦，明天再聊"，不突然断开
- 接近阈值 80% 时日志 + 前端预警

**Docker 资源限制**：
```yaml
services:
  asr:
    deploy:
      resources:
        limits:
          cpus: '2.5'
          memory: 4G
```

**超时与埋点**：所有外部 API 设超时 + 有限重试；埋点记 VAD/EOT/ASR 耗时/LLM 首 token/TTS 首音频，重点盯后两个（决定用户感知）。

## 7. 分阶段实施步骤

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 | docker-compose 骨架 + asr 服务（SenseVoice）+ **场景测试（快语速/断续/背景噪音）** | 传音频能出文本 |
| P2 | backend 骨架 + client 连接 + ASR 链路 | 说话能出文字 |
| P3 | 接 LLM（deepseek-flash） | 文字对话通 |
| P4 | 接 TTS（seed-tts-2.0） | 能出声 |
| P5 | 状态机（VAD + EOT 静音版，**滞回参数可配置**） | 能自然连续对话 |
| P6 | 情感 + 记忆 + 人设 + 内容过滤 + 配额 | 有情感、记得人、安全、有成本上限 |
| P7 | 打断 + 预推理/回滚（**单独分支开发，不合并主干**） | 能插话、低延迟 |

## 8. 成本估算（一个小孩，每天聊 1 小时）

| 项 | 费用 |
|---|---|
| ASR（本地） | 0 |
| LLM（deepseek-flash，预推理关闭时） | ~0.2 元/时 |
| TTS（seed-tts-2.0） | ~2 元/时 |
| **合计** | **~2.2 元/时**（vs 路线 A 8.6 元/时，省 74%） |

> 注：开预推理后，因回滚 LLM 成本会小幅上浮，预推理锁能抑制但不会归零。

## 9. 关键决策与风险台账

**决策**：ASR 本地 SenseVoice（Docker 抹平部署难度，免费+带情绪）；LLM/TTS 云 API；客户端浏览器页起步。

| 风险 | 影响 | 缓解 |
|---|---|---|
| 预推理频繁回滚，LLM 调用变多 | 成本超支 | 短 partial 不启动 LLM；连续回滚临时关预推理 |
| TTS 播放回声触发误打断 | 一句话被自己打断 | AEC + SPEAKING 态提阈值 + 最小人声 150ms |
| SenseVoice 长句延迟、背景噪音掉字 | 感知延迟/错字 | 超时强制分片；滑动窗口；int8；降噪 |
| LLM 情感格式错乱 | TTS 不生效/报错 | 严格标记 + 正则提取 + 失败降级中性 |
| 上下文无限累积 | 成本涨、变慢 | 窗口截断；长期记忆异步、触发式检索 |
| 长时间会话内存泄漏 | 跑久卡顿 | 序号+丢迟到包+水位控制 |
| SenseVoice 占满 CPU | 整机卡顿 | docker 资源限制 + int8 量化 |
| 儿童内容安全 | 不合适输出 | 本地词表过滤（自用也要做） |
