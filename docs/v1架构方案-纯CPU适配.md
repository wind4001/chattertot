# v1 架构方案：纯 CPU 适配（R5 5600X）

> 【项目总监：基线文档 / ADR】
> 状态：**已定案（方向 1 务实降级）**，经 2026-09-27 benchmark 实测后更新
> 关联：`全球开源ASR与语音端点方案调研.md`（调研）、`问题与方案讨论-声纹与判停.md`（问题定义）、`阶段0-Benchmark实测结果.md`（实测数据）

---

## 0. 前提修正（根本）

目标硬件 **AMD R5 5600X + 32GB + RX 6700 XT（Windows）**，AMD 显卡 ROCm 不可用，**实际纯 CPU 推理**。

三条顶层约束：
1. 端到端 ASR 推理 **<800ms，理想 <500ms**。
2. **FunASR-TSE 永久搁置**（换 NVIDIA 卡前不做）。
3. 语义 EOT + tentative 预生成强依赖流式 partial —— 实测证明流式 ASR 精度不足，**v1 剥离**，下放 v2。

---

## 1. Benchmark 结论（决定方向的关键）

| 模块 | 结果 | 决策 |
|---|---|---|
| 声纹 CAM++ | 45~72ms（2~5s 音频） | ✅ 沿用现有 CAM++ |
| Zipformer 流式延迟 | 首 token 56ms，RTF 0.048 | ✅ 延迟极好 |
| Zipformer 流式精度 | 真实儿童语音胡言乱语 | ❌ 致命，弃用 |
| SenseVoice 精度 | 原始音量即正确识别 | ✅ v1 主 ASR |

**核心矛盾**：EOT + tentative 需要流式 partial；但流式 ASR（Zipformer）精度差到 partial 不可用；SenseVoice 精度好却非流式。

**取舍定案**：儿童场景下 **识别正确率 > 低延迟预生成**。v1 放弃流式 partial 驱动的语义 EOT + tentative，保识别精度，用「自适应静音 EOT」替代。

## 2. v1 最终架构（方向 1）

```
麦克风音频流(16kHz PCM)
→ Silero VAD（MIT，主 VAD）持续检测人声；TEN VAD 仅作备选对比实验
→ CAM++ 声纹提取（45~72ms）
    ├─ 相似度 < 0.5 → 丢弃，不进 ASR（省 CPU）
    └─ 匹配 → 缓存整段语音，持续监听静音
→ 自适应静音 EOT（仅基于 VAD 静音时长，不依赖 partial 文本）
    滑动窗口统计历史静音间隔 → p50/p90
    静默阈值 = clamp(p50, 400ms, 1200ms)（仅统计用户说话片段间静音，AI 播放后静默不计入）
    静音阈值 clamp(400~1200ms) + 音频最大缓存 10s（防无限累积）
→ SenseVoice 整段识别（非流式，精度好）
→ DeepSeek V4 Flash（云端 API，v1 不部署本地量化 LLM）；超时/错误 → 播兜底话术回监听
→ 豆包云端 TTS
→ TTS 播放期间：检测人声 ≥150ms 即打断停 TTS（短音频声纹不可靠，不做校验）；声纹过滤留给整段判停后
```

### 补偿优化（缓解静音 EOT 缺陷，v1 内置）

1. **双阈值静音**：短静音=候选暂停，长静音=确认 EOT 提交。
2. **静音阈值 clamp(400~1200ms) + 音频最大缓存 10s**：静音阈值自适应（上限 1200ms 即兜底），音频最大缓存防说话不停时音频无限累积。
3. **LLM prompt 约束**：输入句子疑似不完整时，主动追问"你还想说什么吗？"。
4. **埋点日志**：记录误触发 EOT 案例，后续调参。
5. **Barge-in 打断**：TTS 播放期间，人声持续 ≥150ms 即打断停 TTS（实测 150ms 短音频声纹相似度仅 0.013，不可靠，故打断不做声纹校验）；声纹过滤由打断后整段判停的正常流程完成。
6. **LLM 熔断降级**：云端请求超时（3s）/错误时，TTS 播兜底话术"刚刚我没听清，你再说一遍好吗？"，系统回到监听。

### 边界预案（小孩断断续续）

SenseVoice 识别文本「**<3 字 且 无句末标点**」→ 判定半截话，不生成回答，回到继续监听。
（⚠️ 不能用纯字数判断，否则"好/对/不要/讲吧"等简短应答永远无回复。）

## 3. v1 禁止清单

1. 不部署 FunASR-TSE、TEN TurnDetection（7B 语义 EOT）。（注：TEN VAD 与 TurnDetection 是两回事，仅 TurnDetection 被禁。）
2. 不做儿童语料微调（MyST 禁商用 / ChildMandarin 许可待核）。
3. LLM 不做本地量化（保持云端 DeepSeek V4 Flash）。
4. 不折腾流式 ASR 精度（Zipformer 已实测弃用；Qwen3-ASR 可并行小实验，不阻塞主线）。

---

## 4. v1 / v2 roadmap

### v1（当前纯 CPU）
- Silero VAD + CAM++ 声纹前置过滤
- 自适应静音 EOT
- SenseVoice 整段 ASR
- 云端 LLM + 人设记忆 + barge-in 打断
- 短板：无流式 partial、无语义 EOT、无预生成

### v2（升级 N 卡后）
- 高精度流式 ASR 拿 partial
- 语义 EOT + tentative 预生成
- 可选 FunASR-TSE 语音分离

---

## 5. 遗留风险

1. **CPU 多核争抢**：VAD/声纹/ASR 抢占 6 核。缓解：Docker CPU 配额隔离、音频链路优先级拉高。
2. **重叠语音**：无 TSE，孩子+家长同时说话声纹被污染→大概率丢弃。产品层面接受。
3. **静音 EOT 误判**：小孩停顿久会被误判说完。靠双阈值 + 兜底 + 边界预案缓解，埋点调参。

---

## 6. 一句话总结

调研文档的**三层过滤（VAD→声纹→ASR）保留、声纹前置一票否决保留、自适应静音 EOT 保留**；**砍掉 GPU 依赖（TSE）与流式 partial 依赖（语义 EOT + tentative）**，ASR 定 SenseVoice，LLM 保持云端，把识别正确率放在低延迟预生成之上。
