## 一、项目背景（一句话）

桌面端 AI 语音情感陪伴（给小朋友用），级联方案：本地 SenseVoice ASR（Docker）+ 云端 DeepSeek V4 Flash LLM + 云端豆包 Seed-TTS 2.0，纯 CPU 机器（AMD 5600X）。

---

## 二、当前核心问题（阻塞，P0）

### 问题 1：唤醒词方案不实用（已决定废弃）

- **现象**：sherpa-onnx KWS 唤醒词「小月小月」，用 TTS 生成的音频测试能命中，但**孩子的真实发音说十次只命中一两次**，阈值从 0.25 降到 0.1 仍不行。
- **根因**：KWS 模型对儿童真实语音（音调高、发音不标准、麦克风噪声）鲁棒性差。
- **教训**：当初用 TTS 合成音频测通过就以为可用，测试方法错了——合成音频 ≠ 真实儿童语音。
- **决策**：放弃唤醒词，回到「直接说话 + 声纹过滤」方案。

### 问题 2：打断的短音频声纹不可靠

- **现象**：打断需要"快速判断是不是孩子在说话"，但短音频的声纹提取不可靠。
- **实测数据**（同人音频，不同时长片段 vs 完整参考）：

| 片段时长 | 相似度 |
|---|---|
| 500ms | 0.06 |
| 1000ms | 0.59 |
| 2000ms | 0.94 |

- **结论**：声纹要 **2 秒以上音频才可靠**。打断时孩子只说了 1 秒（如"停"），辨不出是谁。
- **拟方案**：打断改为「累积 2 秒 → 声纹验证 → 是孩子才打断」，代价是延迟约 2 秒，且孩子得说完整的话（"停一下我想说别的"），单字"停"打断不了。

### 问题 3：回声（外放场景）

- **现象**：AI 的语音从扬声器漏进麦克风（回声），能量 VAD 分不清"回声"和"孩子说话"。
- **后果**：之前做 barge-in 打断时，回声误触发打断、还污染判停（孩子说完后回声让 `is_speaking` 一直为 True，判停迟迟不触发）。
- **拟方案**：累积声纹验证能过滤回声（回声的声纹 vs 孩子声纹不匹配 → 不打断）；或用耳麦从物理上消除回声。

## 三、待优化点（按优先级）

| 优先级 | 项 | 说明 |
|---|---|---|
| P1 | 判停自适应 | 当前固定 800ms 静音判停。孩子说话慢/爱停顿，>800ms 被误判"说完"。之前做过 p50 中位数自适应，有"只会往下收敛"的 bug，需改用负反馈闭环（判停后用户 2s 内又说话 → 阈值上调） |
| P1 | VAD 升级 | 当前用能量 RMS 阈值（300），分不清"人声"和"咳嗽/拍手/电视噪声"。拟换 Silero VAD（MIT、1M 参数、CPU 实时） |
| P2 | 识别精度 | SenseVoice 对儿童语音的识别（实测优于 Zipformer streaming，但儿童口齿不清/低音量仍可能漏识）。可试热词 biasing 或更强的 ASR |
| P2 | 端到端延迟 | 判停 800ms + ASR ~200ms + LLM 首 token + TTS 首包，整体响应约 1.5~2.5s，对实时对话偏慢，可考虑 tentative 预生成（但之前放弃过流式 partial） |
| P2 | debug_audio 累积 | 调试用的 `debug_audio/` 无脑累积 wav，需加开关或自动清理 |
| P3 | 多用户 | 当前单用户（一个孩子）。将来多孩子/多人需声纹库 + 说话人识别 |

## 四、已解决（简要记录，供参考）

1. **声纹 text-dependent vs text-independent 矛盾**：注册用唤醒词文本（text-dependent）无法验证对话任意文本（text-independent），导致"对话全被过滤没声音"。已改为"说一句长话注册 text-independent 声纹"。
2. **声纹注册污染**：早期注册用 18s 混合音频（孩子+家长），参考声纹被污染。已改为"说长话（≥1.5s）+ ASR 有效性检查"。
3. **多轮记忆**：LLM 从无状态改为 PostgreSQL 持久化全局历史（最近 20 条）。
4. **声纹阈值**：实测孩子 0.745 / 家长 0.16~0.36，阈值 0.35 → 0.5，可靠区分。
5. **测试隔离**：测试用独立库 lym_test + 端口 8081，不再污染生产库。

## 五、请豆包重点判断的技术权衡点

1. **打断延迟 2 秒可接受吗？** 孩子插话，AI 要 2 秒才停（且孩子得说完整的话）。有没有更好的打断方案（在纯 CPU、外放/耳麦、无 TSE 的前提下）？
2. **「直接说话 + 声纹过滤」是否够用？** 对话期间靠声纹（长音频 0.745 vs 0.16~0.36）过滤家长，不加唤醒词门控。家长在对话期间插话，声纹能可靠过滤吗？还有什么边界情况？
3. **耳麦 vs 外放**：回声问题在外放下难根治（软件 AEC 有限），耳麦能物理消除。产品层面应该建议孩子用耳麦，还是接受外放的局限？
4. **判停自适应**：负反馈闭环（判停太早→阈值上调）是否是当前纯 CPU 下最务实的判停优化？还是有更成熟的方案？
5. **KWS 对儿童语音不鲁棒**：这是 sherpa-onnx 中文模型的普遍问题，还是"唤醒词"这个方向本身在儿童场景就不该用？有没有对儿童发音更鲁棒的唤醒词方案（值得的话）？
