## 一、状态机

```
┌──────────────────────────────────────────────────────┐
│ IDLE（待机）                                          │
│  · 所有语音段送 KWS 检测唤醒词「小云小云」              │
│  · 未命中 → 忽略；命中 → 转 ACTIVE                   │
│  · 声纹：无（本轮尚未开始）                            │
└───────────────────┬──────────────────────────────────┘
                    │ 命中唤醒词
                    ▼
┌──────────────────────────────────────────────────────┐
│ ACTIVE（活跃对话）—— 本轮从唤醒持续到静默超时           │
│                                                       │
│  ┌─ LISTENING（busy=False）                          │
│  │   VAD 判停(800ms) → 声纹 → ASR → LLM → TTS         │
│  └─ BUSY（busy=True，含客户端播放期）                 │
│      · 麦克风语音 → KWS 检测唤醒词 → 命中即打断         │
│      · 非唤醒词 → 不打断（AI 继续播）                  │
│                                                       │
│  · 静默 30s（从客户端播完 AI 语音起算）→ 回 IDLE       │
│  · 回 IDLE 时释放本轮声纹                              │
└──────────────────────────────────────────────────────┘
```

**两个核心区分**：
- `busy`：AI 是否在"占用输出"（含客户端播放期，见 §2.3）
- `seq`：轮次序号。所有异步任务在结束时校验 `seq == my_turn` 才复位状态——
  防止**被取消/被取代的旧任务**干扰新轮次

## 二、关键设计决策（每条都是踩坑换来的）

### 2.1 声纹是「每轮对话自成」，不是全局注册

**做法**：唤醒句（≥1.5s）或唤醒后第一句长话 → 提取声纹作为**本轮**目标声纹 → 本轮用它过滤家长 → 静默超时释放。

**为什么不全局注册**：
- 全局注册**只做一次**，一旦注册错（例如采集时是家长在说话）就**永久失效**，且没有自愈路径
  —— 本项目实际发生过：库里存成家长声纹 → 孩子说话全被过滤 → 表现为"没反应"
- 每轮自确立**天然自校正**：这轮错了，下轮重新确立就恢复

**为什么不从唤醒词音频直接取声纹**：唤醒词只有 ~1.5 秒，声纹不可靠（见 §4）。
故规则是"唤醒句够长（≥1.5s）就用它，不够就等唤醒后第一句长话"。

### 2.2 `busy` 必须在**所有**进入 `process_turn` 的路径置位

**坑**：`finalize_turn()` 里会设 `busy=True`，但**唤醒路径/打断路径是直接调用 `process_turn` 的**，没设。
后果：处理期间 `busy=False` → 孩子重复说的话被当成**新一轮并发处理** → **两段 TTS 同时下发，客户端播放混乱**。

**修复**：把 `busy = True` 放进 `process_turn` 自己开头（不依赖调用方）。

**教训**：状态标志的置位要**收敛到状态拥有者内部**，不要分散在多个调用方——否则必漏。

### 2.3 静默计时必须等**客户端播完**，不能按"发送完成"

**坑**：服务端把 TTS 音频按**网络速度**一次发完（43 秒的故事 2~3 秒就发完），
然后就开始计静默 → 30 秒后判超时回待机 → **但客户端还在播**，孩子听到一半就被要求重新唤醒。

**修复**：客户端在播放队列**真正播完**时发 `{"type":"play_end"}`；服务端收到才 `busy=False` 并开始计时。
兜底：若 `play_end` 未按时到达，按已发 PCM 字节数估算播放时长（`bytes / 48000` 秒）。

**附带收益**：播放期间 `busy` 一直为 True → 麦克风拾到的回声被忽略，减少误触发。

### 2.4 唤醒词与内容同句 → **直接回答**，不要先播"我在的"

**坑**：孩子说「小云小云，你能唱首歌吗」，程序先播「我在呢！」再跑 ASR+LLM 出歌。
中间那几秒空档让孩子**以为没听到** → 他重复了一遍 → 两首歌。

**修复**：唤醒句里已经剥出内容 → **跳过问候语，直接回答**。

### 2.5 唤醒词剥离要**容忍同音字**

**坑**：孩子说「小云小云」，ASR 可能听成「小月小月」→ 精确匹配剥不掉 → 唤醒词泄漏成内容 →
LLM 一本正经地去回答"小月小月"。

**修复**：先精确匹配，再放宽匹配同音字（云/月/运/韵/允）。已验证不误伤"小松鼠""小红帽"等正常开头。

### 2.6 ACTIVE 中只说唤醒词 → 忽略，不要当问题

孩子对话中只说「小云小云」（无内容）时，不应把它送 LLM（会得到莫名其妙的回复）。
判据：剥掉唤醒词后为空 → 忽略。

### 2.7 打断必须用**唤醒词**，不能用声纹

见 §4：**短音频（<1.5s）声纹不可靠**，而打断时孩子往往只说一两个词。
用唤醒词作打断的显式意图信号不受音频长度限制；声纹只用于**较长语音段**的说话人过滤。

## 三、音频前端（回声是关键）

外放场景下，AI 自己的声音会漏进麦克风（回声），这是打断失效的头号原因。
**根因常常不是算法，而是一个没写的 `getUserMedia` 参数**：

```js
getUserMedia({ audio: {
  echoCancellation: true,
  echoCancellationType: "system",
  noiseSuppression: true,
  autoGainControl: false,   // ★ AGC 默认开启，会放大回声残余、破坏 AEC
}})
```

实测（AI 外放播放期间，麦克风拾取的能量）：

| | RMS 均值 | 峰值 |
|---|---|---|
| 修复前（AGC 默认开） | 704 ~ 3880 | **28047** |
| 修复后 | **0 ~ 40** | < 500 |
| 对照：孩子安静说话 | 176 ~ 395 | 2516 ~ 4854 |

修复前是"真人说话"的 2~10 倍 → 拾到的根本不是人声。详见全局记忆 `browser-voice-audio`。

## 四、声纹实测数据（本项目的真实分布）

| 对比 | 相似度 |
|---|---|
| 同人（孩子 vs 孩子） | 0.745 |
| 同人（家长 vs 家长） | 0.720 |
| 异人（孩子 vs 家长） | **0.16 ~ 0.36** |

→ 阈值定 **0.5**（孩子 0.745 远高于，家长 0.36 远低于，分离良好）。

**注意"时长下限"**（同人不同时长片段 vs 完整参考）：

| 片段时长 | 相似度 |
|---|---|
| 500ms | 0.06（≈随机） |
| 1000ms | 0.59 |
| 2000ms | 0.94 |

→ **<1.5 秒不做声纹判定**（这是 §2.7 的依据）。

**历史教训**：早期得出过"一家人声纹区分不开（0.57~0.89 重叠）"的结论——那是**注册音频被多人污染**
（18 秒混合音频）造成的假象。**干净注册后分离度很好**。详见全局记忆 `voice-ai-testing-lessons`。
