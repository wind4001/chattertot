# 待确认清单（火山引擎 / 豆包）

> 项目：桌面端（Electron）AI 语音情感陪伴，对标豆包语音聊天，基于火山引擎。
> 两条候选路线：**A** 端到端实时语音大模型（`realtime/dialogue`）｜ **B** 级联（大模型流式 ASR + 豆包 LLM + Seed-TTS 2.0 / 声音复刻）。
> 下列 10 个问题的答案，直接决定 M3（打断/EOT）和 M4（记忆/情感）的**实现架构**，属于开工前必须消掉的不确定性。
> 请尽量给出**可落地结论 + 官方文档链接**；如端点/参数名有误，请一并纠正。

---

## A. 路线 A（端到端 realtime/dialogue）能力边界

**Q1. 能否外挂自定义长期记忆？**
当前 `dialog_id` 只能带最近 20 轮上下文。我想知道：realtime/dialogue 是否支持注入**自定义的长期记忆/用户画像**（比如通过某个字段传自定义上下文）？还是只能靠 20 轮窗口？
→ 决策影响：决定路线 A 能否承载"记住用户"的陪伴功能，还是必须落路线 B 做长期记忆。

**Q2. `system_role` 能承载多复杂的人设？**
能否写很长的角色设定（几百到上千字：性格/背景/口癖/说话风格/内容边界）？是否有长度或复杂度上限？
→ 决策影响：决定深度人设能否走路线 A，还是需要路线 B 自己控制 prompt。

**Q3. 能否控制情感强度/情感方向？**
realtime/dialogue 输出的语音情感，是由模型自动决定，还是能通过参数指定（如"语气温柔/欢快/克制"，或情感强度数值）？
→ 决策影响：决定路线 A 能否做"用户难过时 AI 也放软"的共情，还是情感只能黑盒。

**Q4. 打断信令归谁管？**
用户抢话时，是**火山云端自动 barge-in**，还是**客户端可以主动下发"打断/停止"信令**（客户端本地 VAD 检测到人声后，发指令停掉火山当前输出）？
→ 决策影响：决定打断检测能否放客户端（低延迟），还是只能依赖云端 VAD（多一层网络 RTT）。

**Q5. `dialog_id` 会话最大轮数？**
"20 轮"是**硬性上限**，还是**默认窗口、可调大**？调大是否有额外成本/延迟代价？
→ 决策影响：决定路线 A 单个会话能承载多长的连续对话。

**Q6. 是否同步返回完整 ASR transcript？**
WebSocket 里能否**开启字段**，同步返回用户说的话 + AI 回复的**转写文本流**（而不仅是音频）？用于后续把 A 会话历史导入 B 会话。
→ 决策影响：**强依赖**。拿不到 transcript，A→B 会话迁移功能直接作废，A/B 完全隔离。

## B. Seed-TTS 2.0 / TTS 情感能力

**Q7. 是否支持显式情感标签输入？**
Seed-TTS 2.0 是**自动**情感（模型自己判断语气），还是**支持调用方传入情感标签**（如 happy/sad/中性，或情感强度）来控制合成语气？
→ 决策影响：决定情感是"可控的"还是"听天由命"，以及 LLM 输出的情感标签能否真正驱动 TTS。

**Q8. 流式合成中，情感标签能否中途动态变更？**
一句话合成过程中，能否**分段动态改情感**（前半句平静、后半句激动）？还是**每段合成只能固定一个情感**？
→ 决策影响：决定能否做到"一句话内部情感渐变"；若不能，降级为"单轮固定情感、仅轮间过渡"。

---

## C. LLM 选型

**Q9. 语音对话用哪个模型？**
`doubao-seed-2-0-mini`（低时延高并发）vs `doubao-seed-2-1-pro`（最新 260915）在**语音对话场景**下的差异：首 token 延迟、单轮成本、情商/对话自然度，推荐哪个？是否有更适合实时语音的专门模型？
→ 决策影响：决定路线 B 的 LLM 默认选型（快 vs 强），以及是否两档混用。

**Q10. 流式输出时序稳定性？**
`doubao-seed-2-0-mini` 流式输出 token 在**网络抖动下是否可能乱序/丢包**？是否带序号需自行排序，还是协议层已保证有序？
→ 决策影响：决定后端编排层是否要自己加序号缓冲/排序逻辑。

---

## D. 成本与复用

**Q11. 路线 A vs B 的成本对比？**
按**每秒/每 token** 计费：路线 A（端到端语音）vs 路线 B（ASR+LLM+TTS 三段）在相同对话时长下的成本大致差多少？双会话模式（A 闲聊 + B 深度陪伴）并存是否划算？
→ 决策影响：决定双链路是否值得同时维护，还是集中做一条。

**Q12. 是否有现成的"角色/记忆"能力可复用？**
火山引擎是否已有**角色扮演模型 / 智能体 / 记忆管理**这类产品能力（如角色扮演 API、Agent 平台），能让我少自研"人设引擎 + 记忆系统"这一块？
→ 决策影响：决定记忆/人设是自研，还是直接复用火山现成能力（大幅省工）。

## 附：目前方案里的关键默认值（请一并对齐/纠正）

- 打断判定：路线 B 客户端本地 VAD，最短有效人声 200ms，渐进式打断（ducking）。
- EOT：v1 规则版（静音 500~800ms + 标点），v2 多特征 + 滞回防抖。
- 情感：LLM 输出情感标签 → Seed-TTS 2.0 合成，情绪平滑器限步长 + 自然回落。
- 音色复刻：Seed-ICL 2.0，5 秒参考音频，仅限本人声音。
